# 复赛 Demo 开发计划

> 千岸 QianAn · 场景一 AI 智能上新
> 队伍：Simon Studio

## 一、Demo 目标

**让评委用一件真实商品，30 秒看到 5 个平台各自合规、可直接导入的上架包 + 合规报告。**

核心要证明的三件事：
1. **端到端跑通**：上传图 + 卖点 → 拿到结果（不是 PPT 演示，是真链路）
2. **规则引擎真在工作**：5 个平台的输出确实不同（不是同一个结果换皮）
3. **合规预检有效**：合规报告真的能检出问题（不是瞎生成）

---

## 二、技术架构（复赛落地版）

```
┌─────────────────────────────────────────────────────┐
│  前端（Next.js + TS + Tailwind）                      │
│  - 上传页：拖拽图 + 卖点输入                           │
│  - 结果页：5 平台 Tab 切换 + 差异对比 + 合规报告       │
└────────────────────┬────────────────────────────────┘
                     │
┌────────────────────▼────────────────────────────────┐
│  后端（FastAPI）                                      │
│  /generate  → 触发 Agent 编排                          │
│  /result    → 轮询/WebSocket 返回进度与结果            │
└────────────────────┬────────────────────────────────┘
                     │
┌────────────────────▼────────────────────────────────┐
│  Agent 编排层（核心）                                  │
│                                                       │
│  主控 Orchestrator                                    │
│    ├─ ① 商品理解 Agent    → Qwen-VL                  │
│    ├─ ② 规则引擎（非 LLM，结构化逻辑）                 │
│    ├─ ③ 文案 Agent        → Qwen-Max（多语言）         │
│    ├─ ④ 视觉 Agent        → Wanx（文生图）             │
│    └─ ⑤ 合规体检 Agent    → Qwen-Max + 规则校验        │
└────────────────────┬────────────────────────────────┘
                     │
┌────────────────────▼────────────────────────────────┐
│  阿里云百炼（算力）                                    │
│  Qwen-Max · Wanx · Qwen-VL · OSS · 函数计算 FC        │
└─────────────────────────────────────────────────────┘
```

**关键设计决策**：
- **规则引擎不是 LLM**，是结构化的 JSON 规则库 + 逻辑代码。这是护城河，不能用 LLM 替代（否则会幻觉、不可控）。
- **Agent 编排用自研轻量框架**（团队有 harness 经验），不上 LangGraph 避免过度工程化。
- **结果异步返回**：用轮询或 WebSocket，因为 5 个平台并行生成要 20-30 秒，不能阻塞。

## 三、五平台差异化实现策略

Demo 阶段不全做满，按"做深 2 个 + 机制复用 3 个"：

| 平台 | Demo 策略 | 工作量 |
|---|---|---|
| **Amazon** | 做深：标题埋词 + A+ 模块 + 五点描述 + 主图白底 | ★★★ |
| **Shopee** | 做深：主图合规检测（禁水印/边框）+ 泰/印尼语本地化 | ★★★ |
| 速卖通 | 机制复用：规则库填好，输出多语标题 + 类目属性 | ★★ |
| Lazada | 机制复用：规则库填好，输出东南亚多语 | ★★ |
| TikTok Shop | 简化：输出商品卡文案 + 一段短视频脚本（不真生成视频） | ★ |

**理由**：Amazon（重内容）和 Shopee（重图片合规）差异最大，做深这两个最能证明"规则引擎"对不同平台真的产出不同结果。其余 3 个用同一套机制（规则库 + 文案 Agent）套用即可，工作量小。

## 四、规则库（核心资产）

Demo 至少要建好这 5 个平台的规则库，存为结构化 JSON：

```json
{
  "amazon": {
    "title": { "maxLength": 200, "mustIncludeKeywords": true, "hint": "埋 A10 搜索词" },
    "mainImage": { "background": "white", "noText": true, "noWatermark": true, "minSize": "1000x1000" },
    "bullets": { "count": 5, "maxLengthPer": 500 },
    "aPlus": { "modules": ["品牌故事", "卖点对比", "场景图"], "requireApproval": true },
    "bannedWords": ["best", "#1", "guarantee", ...],
    "categoryAttrs": { "electronics": ["品牌", "型号", "电压"], ... }
  },
  "shopee": {
    "title": { "maxLength": 120, "perLocale": true },
    "mainImage": { "noWatermark": true, "noBorder": true, "size": "800x800" },
    "description": { "type": "rich_text", "maxLength": 3000 },
    "locales": ["th-TH", "id-ID", "vi-VN"],
    "bannedWords": [...]
  },
  ...
}
```

**来源**：各平台公开的卖家中心规范页，人工整理 + LLM 辅助提取。**不爬平台数据，只用公开规范，合规。**

## 五、开发排期（2 周）

### Week 1：跑通核心链路

| 天 | 任务 | 产出 |
|---|---|---|
| D1 | 百炼环境开通 + API key + 跑通 Qwen-Max/Wanx/Qwen-VL 最简调用 | 3 个 API 都能返回结果 |
| D2 | 建规则库：Amazon + Shopee 的 JSON（手工整理） | 2 个平台的规则 JSON |
| D3 | 写商品理解 Agent + 规则匹配逻辑 | 输入图+卖点 → 输出结构化商品理解 + 命中规则 |
| D4 | 写文案 Agent（Amazon 标题/五点 + Shopee 泰语） | 2 个平台的文案输出 |
| D5 | 写视觉 Agent + 合规体检 Agent | 主图生成 + 合规报告 |
| D6-7 | 后端串成 /generate API（异步）+ 最简前端上传页 | **端到端能跑通**（丑但能用） |

**Week 1 验收标准**：上传一张图 + 卖点 → 30 秒内看到 Amazon + Shopee 的文案、主图、合规报告。

### Week 2：打磨 + 演示准备

| 天 | 任务 | 产出 |
|---|---|---|
| D8-9 | 补齐速卖通、Lazada、TikTok Shop 规则库 + 文案输出 | 5 平台全输出 |
| D10 | 前端结果页：5 平台 Tab + 差异高亮对比 + 合规报告 UI | 演示级界面 |
| D11 | 优化视觉 Agent 提示词，提升出图质感 | 主图达到"能用" |
| D12 | 准备 3 个演示样例商品（覆盖不同类目） | 演示素材 |
| D13 | 录制演示视频（3 分钟，端到端走一遍）+ 写 Demo 说明文档 | 提交材料 |
| D14 | 缓冲日：修 bug、压测、备选方案 | 兜底 |

**Week 2 验收标准**：评委可以用自己的商品或我们的样例，完整体验"一稿 → 五平台上架包"。

## 六、风险与兜底

| 风险 | 应对 |
|---|---|
| 百炼 API 延迟/不稳定 | 预生成部分结果缓存；演示用准备好的样例商品 |
| 视觉生成质量不行 | Demo 可上传"AI 辅助 + 人工微调"的图，诚实说明 |
| 规则库覆盖不全 | Demo 只演示 2-3 个类目（3C/家居/服饰），不贪全 |
| 时间不够 | 砍到只做 Amazon + Shopee 两个平台（核心逻辑不变） |
