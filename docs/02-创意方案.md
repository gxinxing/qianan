**千岸（QianAn）— 一稿多岸的跨境上新 Agent**

## 方案概述

### 要解决的问题
跨境电商卖家把**一个新品**铺到多个海外平台时，要为每个平台、每种语言单独制作一整套上架素材——主图、详情页/A+ 内容、Listing 文案（标题/五点/类目属性）。这套工序**高度重复、强规则约束、且必须本地化**，是跨境卖家最耗时耗钱、最愿意为 AI 付费解决的环节之一。

### 目标用户
- 中小跨境卖家（中国数百万量级）：人手少、缺设计资源、多平台多站点铺货
- 跨境品牌大卖：SKU 多、上新频次高，素材生产是规模化瓶颈
- 跨境 ISV / ERP 服务商：可把本方案作为上架模块集成

### 业务痛点（调研实证）
| 痛点 | 实证数字 |
|---|---|
| 一款产品的 A+/详情页全套素材外包要 1000–3300 元、3–7 天 | CSDN / 什么值得买 |
| 1 套素材 × 5 站点 × 多语种，人工成本与周期直接 ×5 | 卖家社群高频吐槽 |
| 多平台规则各异（Amazon 标题≤200 字符、Shopee 主图禁水印、TikTok Shop 要短视频脚本…），卖家反复踩雷被下架 | 各平台官方规范 |
| Listing 文案多语言靠机翻，转化差且易触发平台合规词 | SellerSprite / ai-indeed |
| 设计师外包慢贵、自拍质量差、纯 AI 出图合规与质感不稳定 | 飞兔拍 2026 行业报告 |

**一句话**：卖家铺一个新品到全球，现在是"几周三万块"；千岸要把它压成"30 秒几十块"。

### 3–5 项核心功能

1. **一稿输入，多平台产出**
   卖家只需上传一张白底主图 + 一段中文卖点描述，系统自动产出 Amazon、速卖通、Shopee、Lazada、TikTok Shop 五个平台各自符合规范的上架包：主图组、详情页/A+ 模块、Listing 文案（标题/五点/类目属性）。

2. **多平台规则引擎（核心差异化）**
   内置各平台规则库（标题字符限制、必填类目属性、主图规范、禁用词、A+ 模块结构等），把"同一商品"翻译成符合每个平台规范的版本——不是简单生成文案，而是**规则感知的本地化重排**。

3. **多语言本地化（非直译）**
   基于百炼多语言大模型，把卖点转化为符合目标市场购物习惯的本地化文案（英语/俄语/泰语/印尼语/西语等），自动校验各平台合规词，避免触发下架。

4. **视觉规范生成（设计师审美）**
   基于百炼文生图能力，按各平台高转化模板生成场景化主图、对比图、卖点图；A+ 模块自动排版，构图/配色遵循设计师级别的视觉规范——这是纯工程师产品做不出的细节。

5. **合规预检与一键导出**
   提交前自动体检：禁用词、字符超限、图片规范、类目属性缺失；通过后一键导出各平台可直接导入的上架包（CSV/图片包/结构化 JSON）。

### 方案亮点
- **差异化护城河一：多平台规则引擎**——市面 Listing 工具多专注单平台生成，千岸做"规则翻译层"，把一个商品适配到多个平台的不同规范。阿里国际（速卖通/Lazada）的多平台场景是天然壁垒。
- **差异化护城河二：设计师级视觉规范**——团队有游戏视觉设计师背景，能把图像生成做到商业可用质感，而非"AI 味"出图。
- **天然契合主办方**：算力用阿里云百炼（多语言 LLM + 文生图），场景服务阿里国际系平台，评审加分项。
- **合规干净**：用卖家自有商品图与卖点，不爬平台数据，无 ToS 风险，演示不暴雷。

### 预期效果
- 单品多平台上架：**从 3–7 天压到约 90 秒**（单平台约 30 秒，5 平台并行约 90 秒）
- 单品素材成本：**从千元级压到几十块**
- 卖家可铺平台数量：**从 1–2 个扩展到 5+ 个**，打开长尾市场
- Demo 路演 wow 时刻：上传一张白底图 → 约 90 秒后大屏同时弹出 5 平台 × 5 语言完整上架包

## 技术方案

### 拟使用的模型或能力（阿里云百炼平台）
| 能力 | 用途 | 百炼对应 |
|---|---|---|
| 多语言大模型 | 卖点→多平台 Listing 文案本地化生成 | 通义千问 Qwen-Max / 多语言版本 |
| 文生图模型 | 白底主图→场景化主图/对比图/卖点图 | 通义万相 Wanx / 百炼文生图 |
| 多模态理解 | 读懂卖家上传的商品图，提取视觉特征 | Qwen-VL 视觉理解 |
| 文本合规检测 | Listing 文案禁用词/敏感词校验 | 规则库 + LLM 双校验 |

### AI Agent / 工作流（核心架构）
采用**多 Agent 编排**架构，主控 Agent 拆解任务并调度专家 Agent：

```
用户输入（白底图 + 中文卖点）
        │
        ▼
  ┌─────────────┐
  │ 主控 Orchestrator │  ← 任务拆解、平台分发、结果聚合
  └──────┬──────┘
         ├── 商品理解 Agent（Qwen-VL 读懂商品类目/材质/卖点/受众）
         ├── 规则引擎 Agent（按目标平台查询规则库，输出约束清单）
         ├── 文案 Agent（按规则 + 卖点生成多语言 Listing）
         ├── 视觉 Agent（文生图 + 模板渲染主图与 A+ 模块）
         └── 合规体检 Agent（禁用词/字符/图片规范/类目属性校验）
         │
         ▼
  多平台上架包（5 平台 × 5 语言）+ 合规报告
```

团队在 AI Agent 编排与工具链上有大量实战积累（deepseek-harness、多个 Skill/CLI 项目），Agent 框架选型与工程化是强项，可保障方案落地。

### 数据处理方式
- **输入数据**：卖家自有商品图 + 卖点文本（无需爬取平台数据，合规）
- **平台规则库**：人工整理 + LLM 辅助提取各平台公开规范（标题字符限制、类目属性、主图规范、禁用词表），存为结构化 JSON 规则库
- **本地化语料**：复用百炼多语言模型内置能力，无需自建翻译语料
- **高转化模板**：从各平台头部Listing/A+ 抽样归纳模板（构图、文案结构），作为视觉与文案 Agent 的 few-shot 示例
- **不留存卖家数据**：处理完即弃，避免合规风险

### 前后端及其他技术组件
| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | Next.js + TypeScript + Tailwind/shadcn | 队长熟悉；上传→生成→展示的交互流，需较好视觉表现力（设计师背景加分）|
| 后端 API | Node/Express 或 Python FastAPI | 轻、快，适配 Agent 编排 |
| Agent 编排 | 自研轻量编排（参考团队既有 harness 项目）或 LangGraph/Dify | 团队有自研 Agent 框架经验 |
| 模型调用 | 阿里云百炼平台 API（指定算力）| 主办方要求 + 多语言/多模态能力齐全 |
| 存储 | 对象存储 OSS（临时存图片产物）+ Redis（任务队列）| 阿里云一体化 |
| 部署 | 阿里云函数计算 FC / 轻量应用服务器 | 题目鼓励用阿里云生态 |

### 技术可行性依据
- 团队已完成多个 AI Agent / LLM 编排 / 多模态项目（游戏视觉资产生成、短视频拉片、多模态 RAG、音乐生成等），技术栈完全覆盖本方案所需
- 百炼平台的多语言 LLM、文生图、视觉理解均为成熟 API，无需自训模型
- 整条链路无不可逾越的技术壁垒，2 周内可跑出可运行 Demo
