# 07 · 交互驱动的功能定义（QianAn 千岸）

> 起因：前一轮按 PM 审查清单补功能（批量框 / 真实图），用户反馈"改了跟之前差不多"。
> 根因不是功能数量不够，而是**所有功能都是"AI 一次性吐包 + 展示"，缺少卖家作为生产者的交互闭环**。
> 本文档放弃"缺口清单"视角，改从「卖家真实作业旅程」出发，重新定义功能。

---

## 一、当前交互现状（基于真实代码读取）

已读页面：`result/[taskId]/page.tsx`、`workbench/page.tsx`、`files/page.tsx`、`admin/page.tsx`。

| 模块 | 现有交互 | 性质 |
|------|----------|------|
| 工作台 /workbench | 单商品表单 → 生成；批量文本框（前端循环调 generate）；进度看板 | 提交入口 |
| 结果页 /result/:id | 流水线进度 → 5 平台 Tab → 差异对比表 → 单平台文案（只读）→ 发布面板 → 合规报告（好评/差评）→ A+ 预览 | 展示 + 单向反馈 |
| 文件库 /files | 包列表 → 展开 json/csv → 整包下载/单文件下载/删除 | 资产管理 |
| 后台 /admin | 指标卡 + 平台覆盖 + 流水线说明 + 经营看板 + 最近任务 | 看板 |

**关键事实**：结果页的标题、五点、描述、属性全部是 `<p>` 只读渲染（第 463/481/494/522 行），没有可编辑控件；主图区在 mock 下显示「Image Pending」（第 546-556 行）。

## 二、卖家真实作业旅程（交互心智模型）

```
我有一个商品（实物/白底图/卖点）
   │
   ▼
[1] 录入：把商品丢进来（一张图 or 几行卖点）
   │
   ▼
[2] 生成：AI 一次性产出 5 平台包（标题/五点/描述/主图/A+/CSV/合规）
   │
   ▼
[3] 审阅：逐平台看——这版行不行？哪里要改？       ← 当前只有"看"，没有"改"
   │
   ▼
[4] 修整：改文案 / 换主图 / 调属性 → 立即知道改完还合不合规  ← 当前缺失
   │
   ▼
[5] 上架：勾选平台 → 一键发到后台（模拟/真实）       ← 当前只有单平台 approved
   │
   ▼
[6] 回收：批量任务的统一审阅台（N 个商品一起看/改/发）  ← 当前批量生成后散落
```

**核心洞察**：步骤 [3][4]（审阅 + 修整）是卖家每天真实在做的事，也是"工具感"的来源。当前产品把它砍掉了——生成的不是最终版，但卖家**在界面上既不能改、改完也不能立刻验证**，只能"再来一稿"（重新生成整个包）。这就是为什么"加功能但感觉没变"：底层能力在涨，生产者交互没涨。

---

## 三、从交互出发重新定义的功能

> 排序原则：**让产品"一眼不同"的，是生产者交互闭环，不是底层能力堆叠**。批量框和真实图是地基，但 F1/F2 才是评委能感知的"产品感"跃迁。

### F1 · 结果页可直接编辑 + 即时合规校验（最高优先级）
- **交互**：单平台文案（标题/五点/描述）变为可点击编辑；输入时实时字符计数（复用 `TITLE_LIMITS` 角标）；失焦或「校验」按钮触发即时合规体检，红色 error 行就地高亮。
- **后端**：新增轻量 `POST /api/validate`（纯规则引擎，复用 `RulesEngineAgent`，**不耗 LLM credit**），接收单字段 → 返回该平台合规结论。
- **价值**：把"AI 吐包 → 人只能重生成"变成"AI 出初稿 → 人改 → 人立刻知道改完合不合规"。这是所有上架工具的标准交互，当前完全缺失。

### F2 · 批量统一审阅台（让"批量"有落点）
- **交互**：工作台"上架后"的批量进度看板点开后，不再是散落 N 个 result 页，而是一个**审阅台**：左列 N 个商品（缩略图+平台数+合规状态），右为选中商品的 5 平台对比；可逐个 approve / 进 F1 编辑 / 触发上架。
- **价值**：批量生成的真正意义是"一次管一堆"，当前批量只解决"一次生成一堆"，没解决"一次管一堆"。F2 让 G1 批量从"壳"变成"真能力"。

### F3 · 多平台一键上架
- **交互**：结果页/审阅台支持勾选多个平台 → 一次 approved → 后端对每个平台跑现有 Playwright 发布（复用 `publisher/runner.py` 状态机）→ 统一展示 N 个上架 job 的状态与截图。
- **价值**：当前 `POST /api/publish` 是单任务单平台、要逐个 approved。卖家心智是"这个商品上 5 个平台"，不是"先发 Amazon 再发 Shopee"。

### F4 · 主图可信度（交互基本盘）
- **交互**：切 `QIANAN_MOCK=0`，主图区从「Image Pending」变成真实生成图（前端已支持 `src` 非 mock 时直接 `<img>` 渲染，第 558-560 行）。
- **价值**：占位主图是"一眼假"的破窗，直接消解所有视觉卖点。属可信度地基，非产品力跃迁。

### F5 · 旅程连续性（信息架构收口）
- **交互**：工作台"上架中/后"的任务卡可直接点进对应 result 页；result 页"再来一稿"回到工作台带预填。让 workbench 与 result 从"两个世界"变成"同一旅程的两段"。
- **价值**：消除当前"提交在 workbench、看结果在 result"的割裂感。

## 四、优先级与 ROI

| 功能 | 让产品"一眼不同" | 实现成本 | 是否耗 credit | 建议 |
|------|------------------|----------|---------------|------|
| **F1 编辑+即时校验** | ★★★★★ | 中（前端可编辑 + 1 个规则引擎端点） | 否 | **第一刀** |
| **F2 批量审阅台** | ★★★★☆ | 中（前端聚合，复用现有数据） | 否 | 第二刀（承接 G1） |
| F3 多平台上架 | ★★★☆☆ | 低（复用现有 publisher） | 否 | 第三刀 |
| F4 真实主图 | ★★★☆☆ | 低（切 env） | 是 | 演示前必做 |
| F5 旅程连续 | ★★☆☆☆ | 低（路由/预填） | 否 | 顺手做 |

## 五、结论

"改了跟之前差不多"的真因：**此前补的是底层能力（批量/真实图），不是生产者交互**。卖家旅程里最值钱的 [审阅→修整] 闭环（F1）和 [批量→统一管] 闭环（F2）都没碰。

下一步建议从 **F1** 动手——它不耗 credit、改动集中、且能让评委在结果页"看到人在用这个工具改东西"，这是产品感最直观的跃迁。
