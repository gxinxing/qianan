# 千岸 QianAn — 决赛路演讲稿与 Agent 架构演进说明

## 一、核心亮点：从 Pipeline 到真实 Swarm Agent 的跃迁

在传统的跨境电商上新工具中，绝大多数系统本质上只是 **单向线性的 Pipeline 流水线**：固定的步骤（理解 → 规则匹配 → 批量文案 → 导出），缺乏根据市场反思、自我修正与动态规划的能力。

千岸 QianAn 在本次重构中，彻底抛弃了死板的流水线逻辑，实现了 **基于共享黑板（Blackboard）的多 Worker 分布式蜂群（Swarm Agent）与自进化系统**。

---

## 二、架构演进对比

| 维度 | 传统 Pipeline 流水线 | 千岸 QianAn 蜂群 Agent 架构 | 评委关注点 / 商业价值 |
|---|---|---|---|
| **任务调度** | 代码死板硬编码步骤，顺序不可变 | **Supervisor 主控基于黑板自主决策**：动态感知市场风险，生成 Action Table，实时评估前置条件并决定下一步 | 真正具备 Agent 自主规划（Planning）能力，非写死脚本 |
| **Worker 协作** | 一个 Prompt 兼顾写作与自查，容易放过错误 | **专能 Worker 竞选与上下文隔离**：PlatformWorker 专注高转化写作；ReviewWorker 独立审查，看不到写作者推理 | 独立第三方视角审核，杜绝“自己批改自己作业”的幻觉 |
| **质量风控** | 依赖 LLM 自觉，容易出现“假完成” | **代码级硬核断言（Guard & Delivery Gate）**：未审核/存在阻断级 error 强制拒绝交付，且改动后审核自动失效 | 确定性合规底线，确保交付上架包 100% 具备可上架性 |
| **经验演进** | 处理完即忘，每次任务均从零开始 | **Evolution Agent 经验蒸馏闭环**：任务结束后自动提炼合规教训与 `[NO LEAKAGE]` 防御标签，回写长期记忆库 | 越用越聪明，店铺/卖家专属 SOP 自动沉淀 |

## 三、4 大 Agent 机制详解（路演解说词）

### 1. 动态市场感知与防御性写作 (Market Sensing)
> “在 Agent 规划阶段，Supervisor 会主动感知目标平台与类目的竞品高发痛点（如保温杯的‘漏水’、‘电池续航短’）。在生成文案时，自动注入防御性标签 `[NO LEAKAGE]`，直接在五点描述头部回应买家顾虑，大幅提升转化率与抗差评能力。”

### 2. 共享黑板与独立上下文隔离审核 (Blackboard & Isolated Review)
> “为了保证审核的绝对客观，我们的 ReviewWorker 与文案生成 Worker 做到完全的**上下文隔离**。审核者看不到写作者的 Prompt 或中间推理，仅对比商品事实档案与产物本身。同时，黑板采用版本号对齐机制：文案一旦被修改，前次的审核结论在结构上**自动失效**，强制要求重新审查。”

### 3. 基于能力评估的 Worker 竞选 (Worker Bidding)
> “针对 Amazon、Shopee、TikTok Shop 等不同平台的规则特点，系统的 Supervisor 会评估各 Worker 的能力匹配得分（如 Amazon 侧重 A9 249字节压测与埋词，TikTok 侧重短视频 Hook 钩子），动态分发任务给最合适的 Worker 处理。”

### 4. 自进化与经验蒸馏闭环 (Evolution Agent & Memory Store)
> “任务完成后，Evolution Agent 自动触发经验蒸馏，把本次任务中修正的合规问题与高转化表现转化为结构化的 `MemoryLesson`，持久化回写至店铺长期记忆库。在未来的上新任务中，记忆库会自动召回这些教训，实现 Agent 的持续自我进化。”
